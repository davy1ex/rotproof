# Controlled AI Development

Небольшой переносимый комплект для разработки с AI-агентом под контролем владельца. Процесс отделяет анализ и планирование от реализации, фиксирует решения и разбивает работу на проверяемые вертикальные срезы.

## Быстрый старт нового проекта

1. Скопируйте `AGENTS.md` в корень проекта, а `docs/` — в каталог документации.
2. Сохраните `prompts/`, `USE_CASES.md` и `checklists/` в доступном команде месте.
3. Дайте владельцу подготовить продуктовый замысел через [`prompts/draft-product.md`](prompts/draft-product.md). После утверждения поместите согласованный текст в `docs/PRODUCT.md`.
4. Запустите [`prompts/initialize-project.md`](prompts/initialize-project.md), чтобы разобрать проект и получить первый вертикальный срез.
5. Утвердите границы и критерии, затем используйте [`prompts/implement-approved-slice.md`](prompts/implement-approved-slice.md).

Для внедрения в уже работающий проект начните с [`prompts/adopt-existing-project.md`](prompts/adopt-existing-project.md). Он помогает инвентаризировать имеющиеся правила и документы, не затирая их.

## Рабочий цикл

1. Агент изучает правила, документы, код и состояние Git.
2. Агент предлагает сценарий, границы, критерии проверки и открытые решения — без изменений файлов.
3. Владелец утверждает подход и решения, которые относятся к его ответственности.
4. Агент реализует только утверждённый срез, сверяет diff и сообщает о фактически выполненных проверках.
5. Владелец принимает результат и отдельно решает вопрос о commit, merge или публикации.

Подробные варианты приведены в [`USE_CASES.md`](USE_CASES.md).

## Product и PRD

`docs/PRODUCT.md` — единый источник целей продукта, пользователей, ценности и границ. Feature PRD необязателен: используйте [`docs/FEATURE-PRD-TEMPLATE.md`](docs/FEATURE-PRD-TEMPLATE.md), когда требований к отдельной фиче недостаточно описать одним сценарием и критериями. PRD уточняет `PRODUCT.md`, а не дублирует его.

## Skill

Для старта отдельный skill не нужен. `AGENTS.md` задаёт постоянные правила проекта, prompts запускают отдельные сценарии. Если позже понадобится вызывать workflow короткой командой в нескольких проектах, skill можно добавить как тонкую оболочку над этим комплектом, не создавая вторую версию правил.

## Настройка под проект

Замените заполнители в документах на сведения, подтверждённые владельцем. Отмечайте `Draft`, `Proposed` и `Accepted` по фактическому статусу. Не переносите в шаблоны конкретные технологии, контракты или архитектурные ограничения без отдельного решения.
